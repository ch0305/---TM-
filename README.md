# 硬件修炼场

目标：从零基础系统学习，走向硬件工程师岗位。  
本项目已安装学习与硬件/电子相关 skill，每次会话应按需加载并遵循本规则。

> **新会话入口**：`AGENTS.md` 会被 OpenCode 在每个新会话自动加载，里面有身份判断（生产 / 独立审核）、开机必读清单、硬门槛与当前基线。你手动翻项目时也请先读它；规则有变动时优先改 `AGENTS.md` 与 `docs/课程生产流程.md`。

## 总原则
- **先体系后内容**：必须先维护完整的「体系结构与进度总览」，再生成具体课程页面。后续新章节必须严格按总览推进，不得临时随意发挥导致遗漏或跳跃。
- **以书为纲、融合优化**：体系与内容以 `书籍/目录/` 为骨架，结合邱关源、李瀚荪、*The Art of Electronics*、*Signal and Power Integrity* 等进行融合优化，形成更适合自学与工程实践的知识路径（见 `docs/体系结构与进度总览.md`）。
- **以大师原著充实细节**：每一课的具体内容都要参考 `书籍/` 中对应书目的具体章节，先定位并理解对应章节讲了什么、如何讲解/推导/举例，再据此组织教学内容与可视化，不凭空编排。

## 课程生产流程（强制，v1.0）
- **教案先行，审核卡关**：每课依次经过「确认排期 → 原著正文摘录 → Markdown 教案 → 独立审核通过 → 生成 HTML → 学习验证与疑问闭环 → 更新进度」。**没有通过独立审核的 Markdown 教案，不得写 HTML 页面**。完整规范见 `docs/课程生产流程.md`。
- **为什么**：旧做法从目录/章节直接生成页面，缺少“怎么把不会的人带到会”的设计，导致页面像信息陈列而非讲课。第一课（试点阶段曾称 L1-01 v2，"v2"只是历史标记、不是并存文件）已验证新流程有效，定为后续所有课的样板。
- **正文优先**：摘录必须是书的正文（扫描件需 OCR + 校对并标印刷页码），仅有目录不算备课完成；教案要区分“原书有的”和“我补的教学设计”。
- **独立审核**：用全新会话、只读教案 + 摘录，按固定 5 问审核；结论必须明确“通过 / 退回”，退回则修改后重审。
- **验证后才转正**：页面生成后要由用户实际走完并反馈，通过才把状态改为“正式”。

## 课程组织与节奏
- **每课 45 分钟**：每个前端学习页面的信息量按高中一节课约 45 分钟可吸收的量来设计，聚焦明确、不过载。
- **按进度推进**：新章节的选题、顺序、前置依赖必须来自 `docs/体系结构与进度总览.md` 的安排；若需调整总览，先更新总览再生成课程。
- **课程可追溯**：每个课程页面应标注所属阶段/模块、对应参考书目章节、建议时长与前置知识。
- **入口与命名（强制）**：`index.html` 是唯一的课程入口，做成导航栏样式，列出“当前课 + 下一课预告 + 文档”。每课**页面**文件名用**中文大写节数 + 教学主题**，例如 `lessons/一 参考方向决定了欧姆定律的正负号.html`；疑问笔记同名放在 `notes/`。内部课号（L1-01 等）用于总览排期**以及摘录/教案文件名**（`书籍/摘录/L1-01.md`、`lessons/drafts/L1-01-教案.md`），不用于页面文件名。

## 教学形式（前端页面）
- **形式**：每次学习内容以前端（HTML + CSS + JS）页面呈现，善用动画、图示、交互控件等可视化方式帮助理解，避免纯文字堆砌。
- **统一模板与风格（已确认：方案 A2「黑板课堂·高密度」）**：所有课程页面使用统一的样式模板与组件体系（固化于 `assets/lesson.css`、`assets/lesson.js`），保证风格一致、交互一致、便于回顾。不得每页随意换风格。**但允许为教学需要新增组件**（如逐步揭示 `reveal`、预测 `pred`、因果链 `chain`、教师口吻 `speak`）：只做增量 CSS/JS，不改已有选择器。模板必须服从教案，不能反过来。
- **布局与信息密度（已固化）**：高信息密度课堂布局，**页面铺满视口（全屏占用）**，上下+左右混排；左右侧栏为**鼠标靠近页面边缘自动滑出的弹出层**（离开后收回）。左栏：本课知识点定位器与章节/课程跳转；右栏：公式速查/节奏/练习进度/疑问索引等辅助信息（内容可按课调整）。提供浏览器全屏沉浸切换按钮（需用户点击触发，Esc 退出）。
- **可视化规范（已固化）**：
  - 可视化服务于理解：用于展示因果关系、变化过程、结构连接、信号/电流/能量流向等，不做无意义装饰动画。
  - 交互优先于静态：涉及变量关系（如 V/I/R、频率/增益等）优先提供可调控件并实时反馈。
  - 标注清晰：图中标明物理量、单位、参考方向/极性、关键节点；动画应可暂停/重看或步骤可控（视内容而定）。
  - 颜色与符号尽量一致：同一类物理量/器件在不同课程中保持一致的视觉语义（以统一模板色板/组件为准）。

## 知识优先级（工程师视角）
- **必会 / 高优先级**：工程实践与后续学习的地基（核心概念、常用公式、典型分析方法）。必须讲透直觉与用法，并在页面中配套练习/自测题（如：$V=IR$、KCL/KVL、分压分流、功率与额定值等）。
- **应会 / 中优先级**：常见但可在使用中巩固的内容。讲清原理与适用场景，可配少量练习或思考题。
- **了解 / 低优先级**：知道其存在、用途与边界即可，当前阶段不深挖、不强记（例如：香农公式等暂不常用的内容）。页面中明确标注“了解即可”，避免喧宾夺主。

## 疑问与便利贴（已落地）
- 终端提出的疑问，按 `docs/疑问标签工作流.md` 写入 `notes/*.json`，再用 `tools/sync_qa.py` 同步到对应课程页面。
- **呈现方式**：疑问以**高可见度标签**锚定在相关环节的知识点附近（不堆积页尾）；点击标签或右侧栏「本页疑问」索引，展开「我的疑问 + 回答 + 小可视化」。若问题挂在尚未揭示的环节，会先展开再跳转。
- **记录原则**：问答可追溯、可回顾，历史问答不删除；`id` 一旦生成不修改；脚本按标记对整段重写，可重复运行不产生重复。

## 归档与回顾
- 遗留的旧页面、原型、样式样例与空笔记已清理；**只保留通过学习验证的正式课程与在排课程**，避免新旧混杂、认错版本。
- 课程、进度、问答与体系文档应保持同步更新，确保“现在学到哪、为什么学这个、下一步学什么”始终清晰。
