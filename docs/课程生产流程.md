# 课程生产流程（强制）

> 状态：**v1.0 正式**。由第一课（试点阶段曾称 L1-01 v2，"v2"只是历史标记、不是并存文件）验证通过——用户实际走完后确认“很有教师的味道，让我学到了不少东西”，并同意定为第一堂课。
> 适用范围：**所有新课（从第二课起）与后续重制课**。遗留旧页面/原型已清理，不再保留；每课只留通过验证的正式版本。

---

## 0. 为什么要有这套流程（根因）

旧流程（`docs/体系结构与进度总览.md` v1.0 §0.5）是：
确认课号 → 看章节 → 设计页面 → 出 HTML → 更新进度。

它缺了两样东西：

1. **没有一份独立于前端的教案**。“怎么把一个不会的人带到会”从未被专门设计，只在写 HTML 时顺带想，于是页面天然变成知识点陈列。
2. **没有独立审核**。预测题泄底、公式被当成无条件真理、独立练习只是例题的近邻复制等问题，要么到页面做完才暴露，要么根本不暴露。

结果就是此前被批评的状态：信息齐全、排版漂亮，**但像资料表，不像老师讲课**。

第一课（试点阶段称 L1-01 v2）在**教案阶段**被独立审核退回两次（第一轮 6 条、第二轮 2 条）并抓出 1 处 A/B 正负端笔误，全部修完才允许做页面；页面完成后用户学习验证通过。因此把这条路径固化为强制流程。

## 1. 六步流程与硬门槛

| 步骤 | 产物 | 硬门槛（不达标不得进入下一步） | 执行者 |
|---|---|---|---|
| 1 · 确认排期 | 总览中的课号、目标、前置、书目映射 | 必须先更新总览，再动课；不得临时插课 | 我 |
| 2 · 正文摘录 | `书籍/摘录/Lx-yy.md` | 必须有**正文**：扫描件 OCR + 人工校对、标印刷页码、区分【原文】/【校对】/【摘录者按】；**只有目录不算备课完成** | 我 |
| 3 · 写 Markdown 教案 | `lessons/drafts/Lx-yy-教案.md` | 结构完整（见 §2）；**此步禁止创建/编辑 HTML** | 我 |
| 4 · 独立审核 | 明确的“通过”或“退回”结论 | 全新会话、只读教案+摘录、按 §3 五问、逐问引用原句；退回则修改后重审，直到通过 | 独立审核者 |
| 5 · 转页面 | `lessons/<大写节数> <教学主题>.html` | 按教案揭示顺序；只做增量组件；答案不提前；资料移页尾；疑问锚真实卡点（见 §4） | 我 |
| 6 · 学习验证与疑问闭环 | 用户反馈 + `notes/*.json` + 页面标签 | 用户实际走完并反馈；终端提问按 `docs/疑问标签工作流.md` 写回；**未获反馈前状态只能是“待验证”** | 用户 + 我 |

**文件命名（强制）**：页面用「中文大写节数 + 空格 + 教学主题」，如 `lessons/一 参考方向决定了欧姆定律的正负号.html`；疑问笔记同名放 `notes/`。`index.html` 是唯一入口，做成导航栏，当前课可点、下一课只做预告。

**两条不可跨越的门**：
- 第 4 步未通过 → **不得写 HTML**。
- 第 6 步未拿到学习反馈 → **不得把状态标为“正式”**。

## 2. 教案必备结构（`lessons/drafts/Lx-yy-教案.md`）

| 小节 | 要写什么 | 作用 |
|---|---|---|
| 一 · 核心问题 | 一个贯穿全课的**具体问题**，学生学完能自己复述 | 防止变成知识点清单 |
| 二 · 讲什么 / 不讲什么 | 明确的边界与留白（含“下一课”钩子） | 控制 45 分钟信息量 |
| 三 · 概念依赖链 | 每一步“因为上一步不够用了”才引入 | 决定讲解顺序 |
| 四 · 逐环节脚本 | 每个环节：教师说什么、板书什么、问什么、何时揭示 | 另一个人拿着就能讲 |
| 五 · 预测题与练习题 | 先只显示题干；注明必须在哪个概念之前提出 | 保证先思考后告知 |
| 六 · 答案区 | 默认折叠；**不得提前泄露后续环节的推导** | 防泄底 |
| 七 · 来源台账 | 逐条标注〔书 p.xx〕/〔通识〕/〔我编的题〕 | 可追溯，不冒充读书 |
| 八 · 给前端的实现约束 | 揭示顺序、组件需求、疑问锚点 | 模板服从教案 |

**教案写作红线**：
- 核心问题必须是**一个**具体问题，且覆盖本课的两种任务形态（如“自己选参考方向算”与“读别人标好的方向算”）。
- 新术语/公式/记号出现前必须有铺垫；学生没学过的写法（如 `V_A − V_B`）不能突然出现在答案里。
- 关键结论要**被推导出来**，不是“背规则”。预测题的答案只揭晓到当前知识能解释的程度。
- 独立练习必须覆盖本课核心难点，**不能是例题的近邻复制**。
- 没摘正文的书，**不引用它的章节号**。

## 3. 独立审核（固定五问）

**审核者设定**：使用全新会话，**只读取** `lessons/drafts/Lx-yy-教案.md` 与 `书籍/摘录/Lx-yy.md`。明确禁止读取 `lessons/*.html`、`assets/*`、`README.md`、`docs/*` 的其他部分——避免被版式带偏。注意 `AGENTS.md` 会被 OpenCode 自动加载，无法"不读"；其第 1 节的**隔离条款**要求审核时忽略其中的当前基线与硬门槛，只按本节五问与两份文件判断。

**固定五问**（每问必须引用教案原句或环节名作证据）：

1. 核心问题是否明确且贯穿全篇？是否覆盖本课的两种任务形态？学生学完能不能自己说出“这节课在解决什么问题”？
2. 每个新概念出现前是否有足够铺垫？有没有突然冒出的术语、公式或记号？指出位置与原因。
3. 关键公式/方法的**来源、用法、适用条件**是否讲清？是被推导出来的，还是只让学生背？学生会不会误以为它是无条件成立的？
4. 预测题/练习是否真的先思考后揭晓？提出顺序与揭示顺序是否自洽（对照第一节与第八节）？独立练习是否覆盖核心难点，还是近邻复制？
5. 零基础学生学完能否独立处理一个**没见过的**同类问题？不能的话卡在哪一步？

**输出要求**：只报真实问题，不夸奖、不提“可进一步丰富”式泛泛建议；最后必须给出明确结论 **通过（可以做页面）** 或 **退回（列必改项，按重要性排序）**。退回 → 修改 → 重审，循环直到通过。

> L1-01 的实际记录：初审退回 6 条 → 复审退回 2 条（预测答案泄底、`u/R` 符号冲突）→ 终审抓出 1 处笔误（第二遍计算把 A/B 正负端写反）→ 通过。这三轮都发生在写 HTML 之前。

## 4. 前端实现约束

1. **开场只显示问题**。学习目标、45′ 节奏表、参考文献、P1/P2/P3 标签、来源台账全部放页尾折叠区。
2. **严格按教案揭示顺序**。预测题必须先选择才解锁揭晓；答案不提前出现；揭晓只到当前知识能解释的程度。
3. **关键推导要“可见地被推出来”**，不能把两条公式并列成卡片让学生自己记。
4. **不要并列卡片化**。用 `.chain` + `.reveal` + `.speak` 体现“上一环不够用了才下一环”的因果链。
5. **侧栏只留真正要随时查的**（公式条件、单位换算、疑问索引）；其余移到页尾。
6. **只做增量 CSS/JS**。新增组件不得改动已有选择器，避免影响其他课程页。模板服从教案，不能反过来。
7. **疑问标签锚在真实卡点**（如“为什么翻个箭头就要加负号”），不预置三个凑数问答；每个环节预留 `QA:stage-N` 标记对。
8. **本地实测清单**：初始 0 个揭示块、预测按钮 gating、揭晓文本不泄底、练习判定正确、进度计数正确、旧课无回归、无 JS 报错。

---

## 5. 疑问闭环

终端提问 → 我回答 → 追加到 `notes/<课程id>.json` → 运行 `python3 tools/sync_qa.py <notes> <page>` → 用户刷新页面看到标签。

完整格式与命令见 **`docs/疑问标签工作流.md`**。要点：`id` 一旦生成不修改；脚本按标记对整段重写，可重复运行不产生重复；七个环节均已预留标记，任何位置都能挂问题。

---

## 6. 状态与归档

**状态流转**：`摘录完成` → `教案待审` → `教案通过` → `页面待验证` → `正式`。

- 遗留页面、原型与样式样例**已清理，不再保留**；每课只留通过验证的正式版本。
- 只有拿到用户实际走完后的反馈，状态才能改为 `正式`；未过审核的教案不得有对应 HTML。
- `docs/体系结构与进度总览.md` 与 `index.html` 必须同步更新状态与入口。
